# IdeaHub Frontend

## Mission

以维护已经投入使用的产品为前提做前端，而不是重新搭一个演示稿。保留 IdeaHub 的原生 ES Module 架构、真实业务内容和已确认的视觉语言；每次改动都要让功能、状态反馈、移动端和无障碍一起成立。

## Success Bar

完成结果应同时满足：

- 用户请求的真实业务流程可操作，不只是在静态页面上“看起来有了”。
- 新界面像 IdeaHub 自己长出来的，不引入 React、Vite、Tailwind、shadcn 或另一套设计系统。
- 桌面与 390px 手机视口无页面级横向溢出，主要触控目标清晰可点。
- 加载、空状态、错误、权限不足和快速连续操作都有明确反馈，不用旧内容冒充新结果。
- 源码可维护，生产 bundle 能构建，UI 验收有可复核证据。

## Workflow

1. 先读仓库根目录 `AGENTS.md`，确认工作区、同步状态和禁止触碰的内容。
2. 读取 [前端架构](references/architecture.md)。涉及样式或新页面时，再读 [视觉与交互规则](references/design-system.md)。
3. 定位现有入口、视图模块、API/mock 合约和相邻页面。优先延续现有模式，不凭想象新造一套。
4. 明确任务属于现有视图修正、新视图、全局组件、样式系统还是数据状态修正，再选择最小但完整的改动面。
5. 只编辑源文件。不要手改 `web/dist/`；生产 bundle 由 `scripts/build-web.mjs` 生成。
6. 实现真实内容、完整状态和响应式行为。涉及异步请求时，处理旧响应覆盖、重复提交和失败后的输入保留。
7. 使用 `ideahub-ui-qa` 完成语法、构建、桌面/手机、交互和浏览器错误检查。
8. 复看实际截图和差异，删掉无意义装饰，确认层级、间距、文案和操作反馈都服务当前任务。

## Decision Rules

- **现有视图还是新视图**：已有业务域内的能力优先进入对应 `web/src/views/*.js`；只有独立导航语义、独立页面状态和明确入口都成立时才新增一级视图。
- **全局还是局部 CSS**：颜色、圆角、阴影、字体和全站断点复用现有 tokens；页面独有结构使用清楚的页面前缀，避免泛化选择器污染其他视图。
- **DOM 还是模板字符串**：延续所在模块的既有写法；不要为了“组件化”引入新框架。重复且容易漂移的结构才抽成小函数。
- **图标**：复用 `web/src/icons.js` 与 `data-ico` 机制，不散落新的内联 SVG，也不用 emoji 代替界面图标。
- **数据状态**：前端字段必须同时核对真实 API 和 `web/src/mock.js`。本地 mock 通过不代表生产契约正确。
- **动效**：复用 `motion.css` tokens，优先一次清楚的状态转换；遵守 `prefers-reduced-motion`，不靠大面积漂浮或延迟动画掩盖加载。
- **依赖**：现有平台能力足够时不加依赖。确需新增 npm 包时同时更新 lockfile，并按 B 类上线交接。
- **视觉变化**：`web/styles.css` 是已确认 UI 的主要样式真源。需求没有要求换视觉时，修功能不能顺手重做品牌和布局。

## Boundaries

- 不修改 `.env`、生产附件、数据库备份或线上环境。
- 不把密钥、内部 token、Cookie 或平台登录状态送到浏览器。
- 不用 `data/uploads/` 的真实附件做公开截图或第三方处理。
- 数据库字段、索引或迁移不属于本 skill；改用 `ideahub-database`。
- Docker、端口、域名、Caddy 和发布操作不属于本 skill；改用 `ideahub-release`。

## Common Failure Modes

- 把一个功能做成孤立 demo，没有接入导航、权限、API、mock 和错误状态。
- 直接复制通用后台模板，导致紫色渐变、同质化圆角卡片和无业务含义的统计块。
- 桌面截图正常就结束，手机出现横向滚动、按钮被挤没或弹窗超出视口。
- 异步切换仍显示上一条数据，让用户误以为点击没有生效。
- 只改 `web/dist/` 或只改 bundle 版本号，源文件没有真实变化。
- 为一个小需求引入完整前端框架，使项目出现双架构。

## Final Review

完成前逐项确认：

1. 入口、标题、操作名称和成功反馈使用同一套词。
2. 加载、空、错、无权限和快速重复操作均有正确状态。
3. 1440×900 与 390×844 都无页面级横向溢出。
4. 键盘焦点、ARIA 当前态、触控尺寸和 reduced motion 没有退化。
5. 改过的 JavaScript 通过语法检查，生产 bundle 和 `npm run test:ui` 通过。
6. 没有把生成物、截图、密钥、备份或真实附件误加入提交。
