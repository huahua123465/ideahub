# IdeaHub 视觉与交互规则

## 视觉真源

样式加载顺序是：

1. `web/styles.css`：结构、组件、响应式与基础 tokens。
2. `web/motion.css`：统一时长、缓动和状态动效。
3. `web/account.css`：登录账户相关样式。
4. `web/soft.css`：当前线上采用的柔和主题覆盖。

不要忽略 CSS 后加载覆盖关系。修改基础 token 前先确认最终值是否被 `soft.css` 重写。

## 当前语言

- 背景和表面使用暖灰白层次，正文是低饱和深灰。
- 品牌色是灰紫褐，不使用高饱和科技蓝或通用紫色渐变。
- 圆角有层级：小控件、卡片和大浮层分别复用 `--r-sm`、`--radius`、`--r-lg`。
- 阴影克制，以区分层级为目的，不制造悬浮卡片墙。
- 中文正文优先现有无衬线字体栈；不要为了单页加载新的远程字体。

始终从现有 CSS variables 派生颜色、圆角、阴影和动效。页面独有语义色可以在页面根节点定义带前缀的局部变量。

## 布局与断点

- `1180px` 是全局导航转为移动抽屉的重要断点。
- `700px`、`560px` 是多数业务页单列化和紧凑布局的主要断点。
- 新模块应在内容需要时响应，不要只按设备名称写特例。
- 页面根节点必须允许 `min-width:0`；内部宽表、时间线或大图使用明确的局部滚动容器，不能撑宽整个页面。
- 390×844 是最低常规手机验收视口；极窄内容还应避免按钮文字被完全挤掉。

## 结构与信息层级

- 页面首屏先说明“这里做什么”和当前状态，再给主要动作。
- 卡片、标签、编号和分隔线要编码真实信息；没有顺序语义时不要加 01/02/03。
- 同一屏只保留一个视觉主角。其余信息靠排版和留白建立层级。
- 空状态告诉用户下一步能做什么；错误信息说明发生了什么和如何恢复。
- UI 文案使用用户认识的业务词，按钮直接描述点击结果。

## 交互与无障碍

- 导航当前项同时维护 `.on` 与 `aria-current="page"`。
- tab 使用正确的 `role="tab"`、`aria-selected` 和键盘移动规则。
- 模态框、抽屉和移动导航打开时管理焦点、背景滚动与关闭入口。
- 移动端主要按钮和表单控件目标高度以 44px 为基准。
- 动效遵守 `prefers-reduced-motion`，不能成为理解状态的唯一线索。
- 点击后立即更新明确的选中或加载状态，网络慢时不要让旧内容留在原处冒充新结果。

## 审美反模式

- 没有业务根据的大数字、渐变光晕和均匀三列卡片。
- 所有元素使用同一种大圆角和同一种阴影。
- 用 emoji 代替正式图标。
- 为了“高级感”牺牲字号、对比度、触控面积或信息密度。
- 动效四处同时发生，让等待更慢、状态更难判断。
- 重做整站视觉来解决一个局部功能问题。
