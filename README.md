# 共享知识库 · IdeaHub

公司内部灵感库。两级流转：**灵感池**（人人可提、人人可见）→ **正式库**（评审采纳后立项）。

底层是**同一张表 + 一个 status 字段**，两级只是视图差异 —— 详见 `docs/架构设计.md`。

---

## 技术栈（刻意选成零构建、极少依赖）

| 层 | 选型 | 需要装什么 |
|---|---|---|
| 前端 | 原生 ES Module + 原型同款 CSS | **什么都不用装**，没有构建步骤 |
| 后端 | Node 内置 `http`（无框架） | Node 20+ |
| 数据库 | PostgreSQL 16 | 生产必需；本地开发可先跳过 |
| 数据库驱动 | `pg` | **全项目唯一的 npm 依赖** |

> 为什么不用 React + Vite：UI 要和给客户看过的演示原型**逐像素一致**。直接沿用原型的 CSS 和 DOM 结构，
> 比重写成组件再对齐可靠得多，而且省掉整条构建链。

## 最省事的启动方式：双击

Windows 上直接双击项目根目录里的：

| 文件 | 干什么 |
|---|---|
| **启动.bat** | 完整启动。自动装依赖、起数据库、建表、灌数据、开浏览器 |
| **启动-仅看界面.bat** | 只跑前端，用内置演示数据。不需要数据库，不需要装任何东西 |

`启动.bat` 会按 6 步走，每一步都会打印结果；任何一步出问题，它会直接告诉你下一步该做什么，
而不是甩一段堆栈。数据库起不来时会自动提示改用「仅看界面」模式。

macOS / Linux 上等价命令：

```bash
node scripts/setup.mjs        # 完整启动
node scripts/serve-web.mjs    # 只看界面
```

## 手动启动（想知道每一步在做什么的话）

### 1. 只看界面（零依赖，30 秒）

前端内置了一份 mock 数据。后端没起时会自动降级到 mock，界面完全可点。

```bash
node scripts/serve-web.mjs
# 打开 http://localhost:5173
```

不用装 Node 包，不用装数据库。

### 2. 完整开发（前端 + 后端 + 数据库）

先准备一个 PostgreSQL：

```bash
# 有 Docker Desktop 的话最省事
docker compose -f docker-compose.dev.yml up -d
```

没有 Docker 就本地装 PostgreSQL 16，然后建库 `ideahub`。

```bash
copy .env.example .env      # Windows
# cp .env.example .env      # Linux/macOS
npm install                 # 只装一个包：pg

npm run db:init             # 建表
npm run db:seed             # 灌入种子数据（含演示里那 9 条灵感）
npm run dev                 # 同时起后端 :3000 和前端 :5173
```

打开 http://localhost:5173

### 3. 部署到服务器

```bash
docker compose up -d --build
```

详见 `docs/架构设计.md` 第八节。

## 团队资料库第一版（2026-08-24）

按《技术3｜IdeaHub团队资料库｜第一版任务表》补的一批能力。四块地基先行，
上层功能都建在它们之上 —— 没有这四块，「统一标签」「全局搜索」「资料关联」互相卡死：

| 地基 | 表 | 解决什么 |
|---|---|---|
| 标签字典 | `tags` + `entity_tags` | 各页面各写一套下拉，「分手」在四个模块里四种叫法 |
| 来源三件套 | 各表的 `source_type/url/ref` | 资料追溯不到出处；外部系统无法幂等写入 |
| 通用关联 | `links` | 需求↔视频↔案例↔客户只能靠人脑记 |
| 机器身份 | `api_keys` | 技术1/技术2 进不来，只能借同事账号 |

在此之上：

- **用户需求**（`/api/demands`）—— 新模块，字段严格照任务表七项
- **全局搜索**（`/api/search`）—— 一条 UNION ALL 跨七类资料，结果标注模块归属
- **客户详情页** —— 九个区，含技术2 写入的两份 AI 分析（分开显示）
- **转案例** —— 客户信息自动带过去，两条记录互相关联，重复点不会建第二条
- **对接口** —— `/api/ingest/*`，见 `docs/接入说明.md`（这份是直接发给技术1/技术2 的）

### 智能导入

顶栏全局搜索旁边的「智能导入」支持直接粘贴聊天记录、客户反馈、会议笔记、
作品复盘或工作总结。服务端通过 `/api/import/analyze` 识别去向并生成结构化草稿，
用户在预览页修改或取消后，再由 `/api/import/commit` 统一写入。

支持灵感池、用户需求、真人/矩阵作品、直播、销售转化、客户档案、后端交付、
案例库和工作提交；不允许绕过评审直接写正式库。AI 不可用时自动退回基础规则识别。

管理员可以直接在智能导入窗口展开「配置模型」，填写 OpenAI 兼容 API 地址和 API Key，
点击「拉取模型」后从该 Key 的真实可用模型中选择一个并保存。页面不会保存或回显密钥；
后端将密钥加密后写入 IdeaHub 独立持久卷，容器重建后仍然有效。普通成员只能使用配置，
不能查看地址或修改密钥。

`.env` 配置：

```bash
OPENAI_API_KEY=              # 只放服务端，不要写进 web/
OPENAI_MODEL=gpt-5-mini
OPENAI_BASE_URL=https://api.openai.com/v1
AI_CONFIG_SECRET=           # 可选；页面配置的独立加密密钥
```

上面三项是没有页面配置时的环境兜底。像苍原算力这类兼容服务也可以只在页面中设置；
输入 `https://ai.cangyuansuanli.cn` 后系统会自动规范成 `/v1` API 地址。

改标签字典要去界面上的「团队 → 标签与对接」，别直接改库：那里同时管着对接密钥，
而密钥明文只在生成的那一刻显示一次。

## 账号与权限

用户名 + 密码登录，账号自己注册。没有接企业微信/飞书。

### 第一次部署：立刻去注册

**部署完成后第一件事就是打开网址注册你自己的账号。**
系统里一个账号都没有时，**第一个注册的人自动成为管理员** ——
这条规则是为了让系统能自己启动起来（否则会卡在「要管理员才能任命管理员」上），
但它也意味着：如果网址先被别人打开并注册，管理员就是别人了。

注册页在这种状态下会直接告诉你「这是第一个账号」，不会让你猜。

### 三种角色

| 角色 | 能做什么 |
|---|---|
| **成员** `member` | 提灵感、投票、评论。新注册的人都是这个 |
| **评审委员** `reviewer` | 以上全部 **+ 采纳 / 否决 / 归档灵感** |
| **管理员** `admin` | 以上全部 **+ 用户管理、撤销采纳** |

角色在界面上改：右上角头像 → 用户管理 → 点角色按钮。改完立刻生效，不用重新登录。

拦截是前后端双层的：普通成员既看不到采纳/否决按钮，直接调接口也会被 403 挡下。
**最后一个管理员不能降级**，否则系统会锁死在没人能任命管理员的状态。

同事忘了密码：管理员进用户管理点「重置密码」，设一个新的私下告诉本人。
重置会同时断掉这个人在所有设备上的登录。没有邮件系统，只能这样。

### 谁可以注册

当前是**开放注册** —— 任何能打开网址的人都能注册进来。

放公网上一段时间后如果发现不认识的人注册进来了，在 `.env` 里填上 `INVITE_CODE`，
注册页就会多一个邀请码框。改完重启后端即可，已注册的人不受影响。

### 安全上做了什么

- 密码用 **scrypt** 哈希（Node 内置，不加依赖），不存明文也不存可逆的东西
- 登录态是 **HttpOnly cookie**，JS 读不到，`SameSite=Lax` 挡掉大部分 CSRF
- 会话存在数据库的 `sessions` 表里，所以「退出登录」和「踢下线」是真的立刻失效
- 登录失败时，「用户不存在」和「密码错误」返回**同一句话、耗时也接近**，
  避免有人靠试错枚举出公司里有哪些账号
- 改密码或被管理员重置后，**其它设备上的登录全部作废**

### ⚠️ 上生产前必须做的一件事

`.env` 里的 `ALLOW_HEADER_AUTH=1` **必须删掉**。

它是给接口自测用的开发后门：打开时，任何人发一个 `X-User-Id: 1` 的请求头就是管理员。
`NODE_ENV=production` 时它会自动失效，后端启动时也会打黄底警告，但别指望这两道保险 ——
删掉它才是对的。

## 定时任务

两件事需要定期跑：热度重算（不然列表会被最早提的灵感霸榜）和超期归档
（给每条没人处理的灵感一个明确的结局）。

任选一种方式：

**A. 系统 crontab（省内存，推荐）**

```cron
*/15 * * * *  curl -sX POST http://127.0.0.1:3000/api/maintenance/recalc-hot
30 4 * * *    curl -sX POST http://127.0.0.1:3000/api/maintenance/archive-stale
0 3 * * *     /opt/ideahub/scripts/backup.sh >> /var/log/ideahub-backup.log 2>&1
```

**B. 常驻进程**

```bash
node scripts/cron.mjs
```

## UI 验收

`npm run test:ui` 已改为复用项目现有的 esbuild 与 Puppeteer，不再需要 Playwright、Sharp、额外浏览器安装或提前启动服务：

```bash
npm run test:ui
```

验收脚本会在内存中构建生产 ESM bundle，并在随机本地端口使用内置 mock 数据检查：

- 今日工作台、项目功能树、灵感池、正式库、统计、样本库、学习中心与内容采集。
- 1440×900 桌面和 390×844 手机视口。
- 页面级横向溢出、移动导航、提交弹窗和 reduced motion。
- 未处理脚本异常与 `console error`。

截图和机器可读报告写入被忽略的 `scripts/.uidiff/`。`report.json` 记录 bundle 大小、每项测量、截图清单和浏览器错误；视觉改动仍需实际查看相关截图，通用 smoke test 也不能替代样本库、附件、Collector 或 API 的专项测试。
