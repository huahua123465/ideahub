# 从这个仓库把 IdeaHub 整套恢复出来

VPS 没了、换机器、或者误删了数据，按这个来。仓库里备份了四样东西：

| 在仓库里的位置 | 是什么 |
|---|---|
| 代码全部 | 服务端 + 前端 + 部署配置 |
| `.env` | 数据库口令、会话时长、OPENAI_API_KEY —— **这是唯一副本** |
| `data/uploads/` | 用户上传的附件本体（客户资料、工作提交的图片等） |
| `backup/ideahub-db.sql` | 整个数据库（用户、灵感、作品、客户、聊天、对标分析……） |

**没有备份的：** `data/pg/`（Postgres 的数据文件目录）和 Caddy 日志。
前者是有意不备份的 —— 见 `.gitignore` 里的说明，简单说就是**照搬它恢复不出来**，
而 `ideahub-db.sql` 装的是同样的数据，且真的能还原。

---

## 恢复步骤

```bash
# 1. 拉下来
git clone git@github.com:<你的账号>/<仓库名>.git ideahub-deploy
cd ideahub-deploy

# 2. .env 已经在仓库里了，不用重新配。确认一下：
grep -c DB_PASSWORD .env        # 应该是 1

# 3. 起数据库（第一次会初始化一个空库）
docker compose up -d db
until docker compose exec -T db pg_isready -U ideahub >/dev/null 2>&1; do sleep 2; done

# 4. 把数据灌回去
docker compose exec -T db psql -U ideahub -d ideahub -v ON_ERROR_STOP=1 < backup/ideahub-db.sql

# 5. 起全套
docker compose up -d --build

# 6. 验一眼
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:18080/api/health    # 期望 200
```

附件（`data/uploads/`）跟着 git clone 一起下来了，位置就是对的，不用额外处理。

> 第 4 步如果报 "relation already exists"，说明这个库已经被初始化过了。
> 先把目标库删掉重建，再重跑第 4 步。
> **那一步会清空目标库，确认过是空机器再执行。**

## 换机器时还要注意

- 对外的 HTTPS 入口不在这个项目里，在 `/opt/ai-stack/new-api/Caddyfile.canvas-media`（见 CLAUDE.md）。
  新机器上要么照着配一份，要么直接用 `HTTP_PORT`（默认 18080）先跑起来。
- `.env` 里的 `HTTP_PORT` 要确认新机器上没被别人占用。

## 怎么验证备份是活的

别等到真出事那天才发现备份是坏的。还原到一个临时库比一比就知道：

```bash
docker compose exec -T db psql -U ideahub -d postgres -c 'CREATE DATABASE restore_check;'
docker compose exec -T db psql -U ideahub -d restore_check -q -v ON_ERROR_STOP=1 < backup/ideahub-db.sql
for db in ideahub restore_check; do
  docker compose exec -T db psql -U ideahub -d $db -At -c \
    "select sum(n_live_tup) from pg_stat_user_tables"
done
docker compose exec -T db psql -U ideahub -d postgres -c 'DROP DATABASE restore_check;'
```
