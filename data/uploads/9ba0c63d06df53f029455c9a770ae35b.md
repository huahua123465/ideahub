# 个人语言形成与人生经历反推系统
## 本地 AI / 算法规范 V1.0

> **用途**：供本地 AI、算法工程、数据工程、研究人员与咨询师共同实现统一分析流程。  
> **分析对象**：客户本人、客户的对象、两人的关系。  
> **反推优先级**：B 家庭成长、E 价值观与自我概念、G 社交圈与信息环境；其次 D 恋爱关系经历、F 重大打击或转折、A 具体人生事件。  
> **版本日期**：2026-08-25。  
> **状态**：可实施的 V1 工程规范；其中明确标注为“工程默认值”的阈值需要在真实案例积累后校准。
## 0. 规范中的三类知识来源
本系统必须区分以下三类内容，防止把工程设计或经验判断包装成科学结论：
| 标记 | 含义 | 使用方式 |
|---|---|---|
| `LITERATURE` | 有权威理论、综述或实证研究支持的原则 | 可进入长期规则库，但仍需标适用人群、语言和场景 |
| `ENGINEERING_DEFAULT` | 为保证系统可运行而设定的阈值、权重和流程 | 不是科学真值；必须可配置、可版本化、可校准 |
| `DOMAIN_HEURISTIC` | 咨询师/业务经验形成的候选解释 | 必须保留替代解释、反证和人工审核 |
语言受到嵌套环境、互动对象与社会文化共同影响；同一表层表现可能由不同经历形成，同一经历也可能产生不同结果，因此反推必须采用多候选解释而不是单路径倒推。[R1][R2][R4][R15]
## 1. 系统目标与非目标
### 1.1 系统目标
1. 从多源自然语言资料中重建可确认的人物、事件、时间线和关系变化。
2. 从长期、多场景语言与互动中识别稳定模式和对象特定模式。
3. 从稳定模式生成内部机制候选。
4. 从内部机制反推 B/E/G 为主的形成经历候选，并生成验证问题。
5. 分别维护客户、对象、关系三层模型。
6. 所有推断可回溯、可反驳、可人工修改、可随新资料更新。
### 1.2 明确非目标
- 不根据少量词汇直接判定人格或人生经历。文本人格关联的总体效应通常有限，且受文本长度、任务和场景明显调节。[R8]
- 不仅凭语言确认具体童年事件、创伤事件、医学或精神诊断。
- 不从语言反推基因或神经特征。遗传研究支持复杂、多基因的语言相关能力差异，但不能对应到具体说话习惯。[R17]
- 不输出伪精确概率，例如“有 87% 概率来自严格家庭”。V1 只输出证据等级、可信标签和推断上限。
- 不把客户对对象的评价当作对象事实。
## 2. 核心推理结构
### 2.1 正向形成链
```text
远端条件（生物、文化、社会结构）
  -> 长期经历（家庭、教育、社交、信息、关系）
  -> 内部机制（自我概念、价值、信任、边界、情绪调节）
  -> 稳定沟通习惯
  -> 当前情境中的语言与互动
```
### 2.2 反向推理链
```text
原始表达
  -> 可观察特征
  -> 跨时间/对象/场景的稳定模式
  -> 多个内部机制候选
  -> 多个形成经历候选
  -> 寻找预期证据与反证
  -> 生成最有区分度的追问
  -> 人工确认或降级
```
反向推理不是把正向箭头机械倒转，而是进行“候选生成—预测证据—反证比较—持续更新”。
### 2.3 七层禁止跳层规则
| 层级 | 对象 | 允许的输出 | 禁止行为 |
|---|---|---|---|
| L0 | 原始资料 | 原文、时间、文件元数据 | 心理解释 |
| L1 | 证据单元 | 谁在何时对谁说了什么 | 将转述视为事实 |
| L2 | 微观观察 | 道歉、请求、否定、回避等可观察行为 | “因此家庭严格” |
| L3 | 稳定模式 | 跨事件/时间/场景重复的模式 | 用同一事件大量消息刷高证据 |
| L4 | 内部机制候选 | 信任、边界、需求资格感等 | 单一确定原因 |
| L5 | 形成经历候选 | 家庭、价值、圈层、关系经历假设 | 确认未被提及的具体事件 |
| L6 | 关系循环 | 触发—解释—反应—反馈—后果 | 只给一方贴标签 |
**硬规则**：没有 L2 不得生成 L3；没有独立 L3 证据不得进入 L4；没有 L4 的多候选比较不得进入 L5。
## 3. 三层分析对象
| 层 | 核心问题 | 主要数据限制 |
|---|---|---|
| 客户本人 | 本人的形成经历、内部机制、稳定表达和关系策略 | 自述可能存在记忆与印象管理偏差 |
| 客户对象 | 对方直接表达、行为模式、态度变化及候选背景 | 经常只有客户视角，必须标来源 |
| 两人关系 | 双方如何相互触发、解释、回应并维持循环 | 不能把关系现象全部归入单方人格 |
自然对话中的意义、身份和关系是在互动序列中共同形成的，因此关系层必须保留轮次顺序。[R5][R6][R10]

## 5. 数据来源与溯源
### 5.1 支持的数据类型
- 原始聊天记录：文本、时间、发送者、引用、撤回标记、媒体附件。
- 朋友圈/社交平台内容：正文、时间、可见范围、评论互动。
- 客户结构化资料：基础信息、关系阶段、明确事件。
- 咨询记录：区分客户原话、咨询师总结、咨询师推测。
- 语音转写：保留音频时间戳、停顿和说话人分离置信度。
- 第三方资料：必须标记来源视角和授权范围。
### 5.2 来源视角枚举
```yaml
viewpoint:
  - subject_direct        # 主体本人直接表达
  - counterpart_direct    # 对方本人直接表达
  - client_about_other    # 客户描述对象
  - consultant_observation
  - third_party_report
  - system_inference
```
### 5.3 数据质量门槛
出现以下情况时必须降级或暂停深层反推：
- 人物身份无法稳定区分；
- 时间戳缺失且无法恢复；
- 仅有截图片段，缺少前后文；
- 只保留一方消息；
- 数据集中于一次强冲突；
- 第三方转述占比过高；
- 关系阶段或对象混合；
- 文本量过少，无法建立个人基线。

## 7. 证据质量与独立性
### 7.1 六维质量
| 维度 | 0 | 1 | 2 |
|---|---|---|---|
| 来源直接性 | 多次转述/系统猜测 | 本人回忆或咨询师概括 | 当时原始表达/记录 |
| 时间接近性 | 多年后模糊回忆 | 近期回忆 | 事件发生时记录 |
| 内容具体性 | 泛化标签 | 有行为但缺细节 | 人、事、时间和后果具体 |
| 重复一致性 | 仅一次 | 同一事件反复 | 不同事件重复 |
| 来源独立性 | 同一消息复制 | 同一来源不同时间 | 不同来源/对象/媒介 |
| 动机风险 | 强讨好/指责/说服 | 存在明显目的 | 低动机或多方印证 |
分数仅用于内部排序，不得转化为真实性百分比。
### 7.2 证据簇与防重复计数
同一次争吵中的 50 条相似消息通常只算一个事件证据簇。下列情况不得增加独立性：复制粘贴、同一转述被多次引用、模型对同一句的多个标签、同一咨询师重复总结。
可提高独立性的来源包括：不同时间事件、不同对象、不同媒介、主体本人直接表达与独立事实记录。
## 8. E0-E5 证据等级与推断状态
| 等级 | 定义 | 典型用途 |
|---|---|---|
| E0 | 仅理论可能，无个案证据 | 不进入个案结论，仅生成检索/追问 |
| E1 | 单一证据簇 | 微观观察或探索性假设 |
| E2 | 同一场景多次重复 | 场景特定模式候选 |
| E3 | 跨时间或跨事件重复 | 稳定/对象特定模式 |
| E4 | 跨场景、对象、媒介或独立来源共同支持 | 较强机制判断 |
| E5 | 有明确本人陈述、客观事实或独立来源确认 | 事实确认；不自动证明因果 |
推断状态与证据等级分开：`unsupported`、`exploratory`、`plausible`、`strong`、`confirmed_fact`。E5 的事实不代表其原因也是 E5。
## 9. 反推上限
| 目标 | 仅凭长期语言的最高上限 | 备注 |
|---|---|---|
| 稳定表达/互动行为 | 高 | 需足够采样和场景校正 |
| 当前价值倾向、自我叙事 | 中高 | 可通过直接陈述和行为一致性提高 |
| 一般家庭沟通特点 | 中 | 需多场景+家庭叙事；不能确认具体事件 |
| 社交圈与信息来源 | 中高/事实 | 明确链接、人物与词汇扩散可确认 |
| 恋爱循环与关系阶段 | 中高 | 直接聊天和时间线可提高 |
| 重大转折时间范围 | 中 | 可发现变点，事件类型仍需证据 |
| 具体童年/创伤事件 | 低 | 仅本人明确提及后才能转为事实 |
| 对象真实内心 | 中 | 只基于其直接语言和行为 |
| 医学/精神诊断 | 禁止 | 转介专业评估 |
| 基因/神经特征 | 禁止 | 不作为输出 |
## 10. 表层特征字典 V1
每个特征必须有定义、纳入规则、排除规则、单位、计算方法、混杂因素、稳定性要求和反推上限。以下为 V1 核心目录。
### F01 明确事实与经历
| ID | 特征 | 操作性定义 | 单位 | 推荐提取方式 |
|---|---|---|---|---|
| `F01.01` | 人物实体 | 识别被提及的人、角色、称呼及别名，并保留是否为本人/转述。 | 消息/文档 | NER+实体消歧 |
| `F01.02` | 关系实体 | 识别亲属、伴侣、前任、朋友、同事、上下级等关系及关系变化。 | 事件 | 规则+LLM分类 |
| `F01.03` | 时间表达 | 提取明确日期、模糊时间、相对时间和持续时间，并区分消息时间与事件时间。 | 表达片段 | 时间解析器+LLM |
| `F01.04` | 地点与迁移 | 识别居住、工作、求学、旅行、迁移等地点及时间段。 | 事件 | NER+时间线 |
| `F01.05` | 教育职业事件 | 识别入学、毕业、转专业、入职、离职、升降职、创业等。 | 事件 | 事件抽取 |
| `F01.06` | 家庭事件 | 识别家庭成员变化、长期冲突、照护、分离、经济变化等明确事件。 | 事件 | 事件抽取+人工复核 |
| `F01.07` | 关系事件 | 识别认识、确定关系、分手、复合、背叛、承诺、失约、冷战等。 | 事件 | 事件抽取+关系阶段 |
| `F01.08` | 事实矛盾 | 识别同一主体对同一事件在时间、角色、原因或结果上的不一致。 | 证据簇 | 规则+语义比对 |

### F02 话题与注意力
| ID | 特征 | 操作性定义 | 单位 | 推荐提取方式 |
|---|---|---|---|---|
| `F02.01` | 话题分布 | 统计长期谈论的主题及其占比，按对象、时期、场景分别计算。 | 时间窗 | 主题分类/聚类 |
| `F02.02` | 反复回到的话题 | 识别跨事件重复出现且未被解决的主题。 | 证据簇 | 语义聚类+时间覆盖 |
| `F02.03` | 主动发起话题 | 区分主体主动引入与被动回应的话题。 | 对话段 | 轮次分析 |
| `F02.04` | 话题回避 | 识别被直接询问后不回应、转移、泛化或结束对话。 | 轮次 | 会话结构分类 |
| `F02.05` | 敏感触发话题 | 识别特定主题出现后情绪、长度、立场或互动行为显著改变。 | 事件 | 变化检测 |
| `F02.06` | 信息来源提及 | 识别平台、博主、书籍、社群、朋友或权威人物的引用和转述。 | 消息 | 实体抽取 |

### F03 词汇与风格
| ID | 特征 | 操作性定义 | 单位 | 推荐提取方式 |
|---|---|---|---|---|
| `F03.01` | 词汇丰富度 | 在足够文本量下计算词汇多样性；需按文本长度和场景校正。 | 时间窗 | MATTR/HD-D等 |
| `F03.02` | 抽象-具体词 | 衡量抽象概念、原则性词汇与具体人事物词汇的相对使用。 | 时间窗 | 词典+模型 |
| `F03.03` | 专业与圈层词 | 识别职业术语、方言、社群黑话、网络梗及来源候选。 | 消息/时间窗 | 词典+新词发现 |
| `F03.04` | 程度强化 | 识别非常、绝对、永远、特别等强化表达及其语境。 | 消息 | 词典+语用校正 |
| `F03.05` | 弱化与缓冲 | 识别可能、大概、有点、我只是、随便等弱化表达。 | 消息 | 词典+语用分类 |
| `F03.06` | 否定习惯 | 区分事实否定、自我否定、他人否定、预防性否定。 | 消息 | 依存/语义分类 |
| `F03.07` | 口头禅与固定模板 | 发现跨时间重复的固定短语、开场、收尾和解释模板。 | 时间窗 | n-gram+语义聚类 |
| `F03.08` | 代词与指涉 | 统计我/我们/你/他们等指涉，但禁止脱离语境直接推人格。 | 时间窗 | 词典+指代解析 |

### F04 句法与信息组织
| ID | 特征 | 操作性定义 | 单位 | 推荐提取方式 |
|---|---|---|---|---|

## 12. 稳定模式聚合
### 12.1 分层基线
必须分别计算：个人总体基线、对象特定基线、场景基线、关系阶段基线、媒介基线。
```text
当前表达 = 个人基线 + 对象适配 + 关系阶段 + 当前状态 + 话题 + 媒介 + 噪声
```

### 12.3 模式类型
- `trait_like`：跨对象、场景和时间稳定。
- `partner_specific`：主要对当前对象出现。
- `role_specific`：主要在工作/家庭权力角色出现。
- `state_like`：只在短期压力或特定事件出现。
- `stage_specific`：只在某关系阶段出现。
- `medium_specific`：只在某平台或公开/私下出现。
## 13. 内部机制库 V1
机制是表层特征和形成经历之间的桥梁，不等同于人格诊断。每个机制必须由多个不同特征组合支持。
| ID | 机制 | 操作性定义 | 常见支持模式 | 主要替代解释 | 反推上限 |
|---|---|---|---|---|---|
| `M01` | 表达安全感低 | 预期表达需求、不同意见或脆弱会带来批评、拒绝或关系损害。 | 请求弱化、立场收回、许可寻求、冲突回避 | 文化礼貌、当前对象反应强烈、职业角色 | 中 |
| `M02` | 需求资格感低 | 认为自己的需要不重要、麻烦或不应该占用他人资源。 | 请求前道歉、自我否定、长期退让 | 临时客气、资源确实不足 | 中 |
| `M03` | 冲突等同关系破裂 | 把分歧理解为爱减少、关系失控或即将结束。 | 冲突中追问确认/撤退、灾难化 | 当前关系确有不稳定信号 | 中 |
| `M04` | 外部认可型自我价值 | 自我价值高度依赖他人评价、被需要或表现。 | 评价敏感、过度证明、失败后自我整体否定 | 绩效型职业/教育场景 | 中 |

| `M20` | 合理化防御 | 用规则、逻辑和宏大解释替代对脆弱和需求的承认。 | 高逻辑密度但回避情绪问题 | 专业讨论本身需要逻辑 | 中 |
| `M21` | 内部归因偏重 | 问题发生时优先认为是自己能力、价值或人格问题。 | 整体自责、自我标签 | 事实责任较高 | 中高 |
| `M22` | 外部归因偏重 | 问题发生时优先认为是他人、环境或规则问题。 | 长期缺乏自我修正、归责他人 | 环境确实不公平 | 中高 |
| `M23` | 复杂归因 | 能够同时考虑个体、关系、情境和时间因素。 | 多重解释、可修正性 | 只是语言能力强 | 高 |
| `M24` | 群体归属依赖 | 身份和判断较依赖圈层认同、共同语言和群体规范。 | 圈层词、我们/他们、规范压力 | 职业共同体正常协作 | 中 |
| `M25` | 身份切换灵活 | 能根据角色和对象调整表达而不明显失去核心立场。 | 对象差异明显且功能适配 | 表面迎合 | 中高 |
| `M26` | 身份切换冲突 | 不同圈层中的表达和价值明显矛盾并产生压力。 | 线上线下冲突、角色话语断裂 | 隐私边界正常 | 中 |
| `M27` | 安全优先 | 在选择中优先稳定、可预测和降低损失。 | 风险语言、稳定价值、避免不确定 | 当前现实风险高 | 中高 |
| `M28` | 自由自主优先 | 在选择中优先个人空间、选择权和不受控制。 | 自主性保护、对干涉敏感 | 对方确实越界 | 中高 |
| `M29` | 忠诚责任优先 | 把持续投入、承诺和不离开置于高位。 | 责任/忠诚规范、对失约敏感 | 具体关系契约 | 中高 |
| `M30` | 面子评价优先 | 对公开形象、羞耻和被轻视高度敏感。 | 公开/私下差异、评价触发 | 职业声誉确实重要 | 中 |

### 13.1 机制生成规则
1. 机制不得由一个词触发。
2. 至少需要两类不同特征，或一类特征跨多个独立场景。
3. 必须同时生成 2-5 个候选机制。
4. 每个候选必须列出预期证据、反证和替代解释。
5. 机制最多达到其 `reverse_inference_ceiling`。
6. 机制与形成经历分开评级。

### 15.1 价值排序算法
不要只统计价值词频。对每个价值候选收集四类证据：
1. 自我声明：他说重视什么；
2. 选择证据：冲突时实际选了什么；
3. 情绪证据：什么被破坏时反应最强；
4. 持续投入：长期把时间、金钱、关系成本投向哪里。
四类证据一致时可提高可信度；自我声明与行为冲突时必须保留差异。

### 16.1 信息来源追踪
- 建立新词/梗首次出现时间；
- 检索同一时期提及的平台、人物、链接和群聊；
- 比较主体与关键关系对象的语言相似度；

- 观点框架相似不等于确定来自某一博主。

## 18. 多候选解释算法
### 18.1 候选生成
```python
def generate_candidates(pattern, rule_cards):
    candidates = retrieve_rules(pattern, rule_cards, top_k=12)
    candidates = filter_by_population_language_context(candidates)
    candidates = group_by_mechanism_and_history_domain(candidates)
    return keep_diverse_candidates(candidates, min_n=2, max_n=5)
```
### 18.2 每个候选必须回答
- 哪些观察支持它？
- 如果它是真的，还应该看到什么？
- 有什么反证？
- 还有哪些不同原因会产生相同表现？
- 该结论最多能到什么上限？
- 问什么最能区分候选？
### 18.3 支持度计算（工程排序，不是真实概率）
```text
support_rank = Σ(独立证据簇 × 质量系数 × 关联直接性 × 场景匹配)
               - Σ(反证 × 反证强度)
               - 单一来源惩罚
               - 场景混杂惩罚
```
数值只用于候选排序。最终状态由证据等级、反证和推断上限共同裁决。禁止把该分数展示为概率。
## 19. 推断裁决规则
| 条件 | 允许状态 |
|---|---|
| 仅 E1 且有多个替代解释 | `exploratory` |
| E2，限于单一场景 | `plausible_context_specific` |
| E3，跨时间但单对象 | `plausible_partner_specific` |
| E4，多类证据且反证较弱 | `strong`，但不得超过反推上限 |
| E5 明确自述/事实 | 事实部分 `confirmed_fact`；原因仍单独评级 |
| 有强反证或数据质量差 | `withheld` 或降级 |
### 19.1 禁止自动输出的句式
- “他小时候一定……”
- “她本质上就是……”
- “这说明她有某种疾病/障碍……”
- “因为用了某个词，所以……”
- “家庭影响占 X%。”
推荐句式：
- “在多个独立场景中可观察到……”
- “更支持 A 机制，但 B/C 仍是替代解释……”
- “该模式与某类家庭沟通规则相容，当前证据不足以确认具体事件……”
## 20. 关系循环引擎
### 20.1 固定序列结构
```text
触发事件
 -> A 的解释
 -> A 的表达/行为
 -> B 的解释
 -> B 的回应
 -> A 的二次反应
 -> 短期收益
 -> 长期代价
 -> 循环强化/削弱
```
### 20.2 常见循环模板（仅作为检索模板）
- 追问—回避；
- 指责—防御；
- 试探—安抚—再次试探；
- 退让—积累—爆发；
- 控制—反控制；
- 请求—拖延—升级；
- 冲突—冷处理—短暂恢复—原问题重复；
- 自责—安抚—问题未解决。
模板只能在至少三个独立事件中出现相似序列后进入稳定关系循环。

### 21.1 阶段与职责

## 22. AI 角色契约
### 22.1 提取器 `extractor`
```text
你只提取原文可直接支持的事实和微观语言行为。
不得推断人格、家庭、创伤、动机或诊断。
每个字段必须附 evidence_id 和 quoted_span。
不确定时返回 null 或 needs_context。
输出严格 JSON。
```
### 22.2 解释器 `interpreter`
```text
输入是已确认的稳定模式，不是原始聊天。
为每个模式生成 2-5 个彼此有区分度的内部机制候选。
每个候选列出支持模式、预期证据、替代解释和反证。
不得直接确认形成经历。
```
### 22.3 经历候选器 `history_hypothesizer`
```text
输入是机制候选、明确时间线和规则卡。
优先生成 B/E/G，再生成 D/F/A。
区分一般沟通环境与具体事件；具体事件无直接证据不得确认。
输出 reverse_inference_ceiling 和最有区分度的验证问题。
```
### 22.4 反对者 `challenger`
```text
你的任务不是完善原假设，而是主动寻找：
1. 反例；2. 场景混杂；3. 来源偏差；4. 替代解释；5. 跳层推理；6. 重复计数。
对每个候选给出 keep / downgrade / reject 建议及依据。
```
### 22.5 裁决器 `adjudicator`
```text
只能依据结构化证据等级、反证、来源独立性和推断上限裁决。
不得新增证据或故事。
输出：status、evidence_level、ceiling、reason_codes、human_review_required。
```

```yaml
  - F05.04 立场收回
  - F06.03 请求前道歉
  - F11.02 许可寻求
mechanism_candidates: [M01, M02]
history_candidates: [B01, B02]
expected_evidence:
  - 跨父母/权威/伴侣出现
  - 家庭叙事含不能顶嘴或需求造成麻烦
contradictions:
  - 仅对当前对象出现
  - 在家庭和工作中长期直接表达
alternatives:
  - 服务型职业规范
  - 地域礼貌规范
population: adult
language: zh-CN

evidence_basis: [R3, R4]
reverse_inference_ceiling: medium
review_required: true
version: 1.0.0
```
文献可以支持概念和一般关系，但不能自动证明个案。测试标准强调每种分数解释和用途都需要独立的效度依据。[R12]
## 24. 人工审核流程
### 24.1 角色
| 角色 | 权限 |
|---|---|
| 业务人员 | 确认人物、关系、数据缺口和明确事实 |
| AI | 提取、聚合、生成候选、检索反证 |
| 咨询师 | 审核机制与经历假设、设计追问、处理复杂语境 |
| 研究人员 | 维护特征字典、规则卡和文献版本 |
| 技术人员 | 模型、数据库、安全、监控和评估 |
### 24.2 审核状态
```yaml
human_status:
  - unreviewed
  - accepted
  - accepted_with_edit
  - rejected
  - needs_more_data
  - frozen_fact
```
人工修改必须记录：原值、新值、理由、证据、操作者、时间和规则版本。
## 25. 无自有实验数据时的验证方案
现阶段验证的是流程可靠性，不宣称已验证人生反推准确率。
### 25.1 可立即验证
- 人物和说话人识别准确率；
- 时间线和事件抽取准确率；
- 原文引用完整率；
- 言语行为/情绪/立场分类的一致率；
- 同一输入重复运行稳定性；
- 证据重复计数率；
- 反证检出率；
- 客户观点误写为对象事实的错误率；
- 违反反推上限的比例；
- 咨询师追溯证据所需时间。
### 25.2 案例积累后验证
- 咨询师之间一致率；
- AI 与咨询师一致率；
- 后续追问证实/推翻假设的比例；
- 高/中/低等级的真实区分度；
- 特征在不同平台、年龄、地域和关系阶段的稳定性；
- 规则版本升级前后的回归测试。
### 25.3 测试集设计
至少包含：正常案例、信息不足、强冲突、单方叙述、自相矛盾、职业礼貌混杂、当前关系特定模式、公开/私下差异、数据截断和第三方转述。
## 26. 本地部署与数据存储
### 26.1 推荐存储
1. 原始资料库：不可变存储。
2. 结构化关系数据库：人物、消息、事件、观察、审核。
3. 向量检索库：相似表达、规则和文献检索。
4. 证据图：证据—观察—模式—机制—经历—反证关系。V1 可先用关系表实现。
5. 规则/文献库：可版本化规则卡和来源。
### 26.2 增量更新
新资料进入后：解析新证据 -> 找受影响的观察和模式 -> 重新运行候选与反证 -> 生成差异记录。不得无痕覆盖历史结果。
### 26.3 模型参数
- 提取与裁决温度低；
- 所有输出严格 JSON Schema；
- 每个输出记录模型、量化方式、提示词和规则版本；
- 失败时返回 `insufficient_evidence`，禁止补全故事；
- 高影响假设必须人工审核。
## 27. 隐私、安全与审计
系统处理高度私密的第三方关系数据，至少需要：
- 本地加密与传输加密；
- 角色最小权限；
- 第三方对象资料的授权和用途限制；
- 原文、结构化事实和推断分区存储；
- 删除、撤回和保留期限；
- 所有读取、修改和导出日志；
- 禁止未经授权用于训练其他模型；
- 低可信深层假设不进入业务事实库；
- 模型和规则事故的回滚机制。
NIST AI RMF 建议把治理、场景映射、测量与风险管理贯穿系统生命周期。[R13][R14]
## 28. 实施路线图
| 阶段 | 交付 | 验收重点 |
|---|---|---|
| Phase 0 基础 | 数据字典、身份/时间解析、权限 | 数据可追溯 |
| Phase 1 事实与观察 | A 时间线 + F01-F13 中高确定性特征 | 原文引用与人工一致率 |
| Phase 2 B/E/G | 机制库、规则卡、候选/反证/追问 | 不跳层、替代解释完整 |
| Phase 3 关系模型 | 三层对象和关系循环 | 顺序分析、视角分离 |
| Phase 4 校准 | 真实案例反馈、阈值与规则迭代 | 等级区分度、错误类型下降 |
MVP 不建议一开始实现全部特征。优先级：明确事实和时间线 -> 言语行为与互动 -> 跨场景差异 -> 机制候选 -> B/E/G 反推。
## 29. 端到端合成示例（仅演示流程）
> 以下内容是合成示例，不代表真实个案或科学概率。
### 29.1 原始片段
```text
客户：不好意思又麻烦你了，你今晚有空的话能不能打个电话？没空也没事。
对象：今天忙，晚点再说。
客户：好的好的，我没有催你的意思，你先忙。
（3 小时后）
客户：是不是我哪里让你不舒服了？你直接说就行。
```
### 29.2 L2 观察
- F06.03 请求前道歉；
- F03.05 弱化；
- F05.04 立场收回；
- F12.04 延迟后追问；
- F09.02 对他人动机/状态进行推断。
### 29.3 L3 模式判定
只有在多个独立事件中重复，才形成“亲密关系中的请求弱化”和“回复延迟后的关系确认”模式。单次片段仍为 E1。
### 29.4 L4 候选机制
1. M01 表达安全感低；
2. M02 需求资格感低；
3. M09 不确定性耐受低；
4. 当前对象确有反复延迟和失约，导致情境性适应。
### 29.5 L5 候选经历
- B01 家庭对话开放度较低；
- B05 认可可能与懂事/不给人添麻烦绑定；
- D03 过去关系中出现反复失约；
- 当前关系特定形成。
### 29.6 反证任务
检查主体对朋友、同事、父母是否同样弱化；检查该模式是否在当前关系前存在；检查对象是否确有多次延迟。
### 29.7 区分性追问
“这种提出需求前先道歉的习惯，在这段关系以前也有吗？小时候你直接提出需要时，家里通常怎样回应？”
## 30. 开发验收清单
- [ ] 每条事实和观察都能回链到原文。
- [ ] 客户视角与对象事实分开。
- [ ] 同一事件不会因消息多而重复加权。
- [ ] L2/L3/L4/L5 不跳层。
- [ ] 每个深层候选至少有一个替代解释。
- [ ] 每个候选都有反证和验证问题。
- [ ] 证据等级与推断上限分别计算。
- [ ] 低质量数据自动降级。
- [ ] 具体童年/创伤事件无直接证据不确认。
- [ ] 人工修改有审计记录。
- [ ] 新资料增量更新且保留历史版本。
- [ ] 模型、提示词、规则和特征字典均有版本号。
