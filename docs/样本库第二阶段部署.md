# 样本库第二阶段部署与验收

第二阶段增加十五维元素拆解、证据、人工决定、标签组合筛选、作品评价和指标趋势。它是在第一阶段 `samples`、`sample_captures`、`sample_assets` 之上的增量结构，不能跳过第一阶段数据库迁移。

## 上线类型

本阶段属于 C 类数据库迁移：

- 重新构建容器不会自动执行 SQL；
- 不修改现有原始档案、媒体目录或旧 `work_analyses.payload`；
- 分析版本、证据和人工决定采用追加保存，回滚应用时应保留新表数据；
- AI 继续使用 IdeaHub 已有的服务端供应商配置，不新增浏览器密钥或 Collector 公网接口。

## 第一次部署顺序

1. 确认 VPS 已完成第一阶段部署，`samples` 三张表和 `/opt/ideahub-samples` 正常。
2. 检查工作区，只允许既有 `.env` 本地配置差异。
3. 备份 PostgreSQL 与样本媒体。
4. 快进拉取第二阶段提交。
5. 执行 `scripts/migrations/20260829-sample-library-stage2.sql`。
6. 重建 API 镜像并切换容器。
7. 运行 `scripts/migrate-sample-research-stage2.mjs`，把旧 `ai_analysis` 与历史互动数据转成第一批研究版本和指标快照。
8. 再运行一次迁移脚本，确认版本、元素、证据和快照计数不增长。
9. 检查健康状态、组合筛选、十五维、人工决定、评价和趋势。

## VPS 命令模板

最终提交后把 `<STAGE2_COMMIT>` 替换成实际完整哈希再执行。

```bash
set -euo pipefail
cd /root/ideahub-deploy

git status --short --branch
git fetch origin feat/content-collector
git pull --ff-only origin feat/content-collector
test "$(git rev-parse HEAD)" = "<STAGE2_COMMIT>"

backup_file="/root/backup/ideahub-pre-sample-stage2-$(date +%Y%m%d-%H%M%S).sql"
mkdir -p /root/backup
docker compose exec -T db pg_dump -U ideahub -d ideahub > "$backup_file"
test -s "$backup_file"

docker compose exec -T db psql -v ON_ERROR_STOP=1 -U ideahub -d ideahub \
  < scripts/migrations/20260829-sample-library-stage2.sql

docker compose exec -T db psql -v ON_ERROR_STOP=1 -U ideahub -d ideahub -Atc \
  "SELECT to_regclass('public.sample_analysis_jobs'),to_regclass('public.sample_analysis_versions'),to_regclass('public.sample_analysis_elements'),to_regclass('public.sample_metric_snapshots');"

docker compose config --quiet
docker compose up -d --build api

docker compose exec -T api node scripts/migrate-sample-research-stage2.mjs
first_counts="$(docker compose exec -T db psql -U ideahub -d ideahub -Atc \
  "SELECT (SELECT count(*) FROM sample_analysis_versions)||':'||(SELECT count(*) FROM sample_analysis_elements)||':'||(SELECT count(*) FROM sample_element_evidence)||':'||(SELECT count(*) FROM sample_metric_snapshots);")"
docker compose exec -T api node scripts/migrate-sample-research-stage2.mjs
second_counts="$(docker compose exec -T db psql -U ideahub -d ideahub -Atc \
  "SELECT (SELECT count(*) FROM sample_analysis_versions)||':'||(SELECT count(*) FROM sample_analysis_elements)||':'||(SELECT count(*) FROM sample_element_evidence)||':'||(SELECT count(*) FROM sample_metric_snapshots);")"
test "$first_counts" = "$second_counts"

for i in $(seq 1 30); do
  if curl -fsS http://127.0.0.1:18080/api/health >/dev/null; then break; fi
  sleep 2
done
curl -fsS http://127.0.0.1:18080/api/health
docker compose ps

docker compose exec -T db psql -U ideahub -d ideahub -c \
  "SELECT count(*) AS dimensions FROM sample_analysis_dimensions;"
docker compose exec -T db psql -U ideahub -d ideahub -c \
  "SELECT v.sample_id,v.revision,count(e.*) AS elements FROM sample_analysis_versions v LEFT JOIN sample_analysis_elements e ON e.version_id=v.id GROUP BY v.id,v.sample_id,v.revision ORDER BY v.sample_id,v.revision;"
```

## 浏览器验收

- 组合选择“女性情感 + 关系判断 + 强结论 + 案例拆解”，结果卡显示四条命中原因。
- 打开一篇样本，四个页签都能使用且不重置列表筛选。
- 元素拆解恰好十五项；可展开证据并看到来源、位置、置信度和确认状态。
- 分别执行确认、人工修订和驳回，刷新后状态不丢，AI 原值仍可见。
- 无 AI Key 时页面明确提示，并且仍能建立人工空白十五维。
- 四种内容目标评价互相独立。
- 趋势区缺失数据显示 `—`，同时存在图和数据表。
- 390px 手机端无页面级横向滚动，点击样本进入独立详情，返回后保留筛选和列表位置。

## 回滚边界

应用失败时可以回滚镜像或代码，但不要删除第二阶段新表，也不要清理第一阶段样本媒体。新表对旧版本应用无侵入，保留它们便于修复后继续使用。数据库恢复必须与同一时间点的样本媒体备份配套，不能只恢复其中一边。
