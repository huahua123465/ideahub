# 右侧聊天面板 —— 实现任务

需求：项目右侧常驻一个对话框，列出所有同事，点谁就跟谁聊，能发文字也能发文件。

## 一、形态

右侧固定面板，两层：

```
[人员列表]            点某人 → [会话]
 张三  ●2                       ← 返回  朱涛
 李四                           ┌──────────────┐
 王五  ●1                       │  消息气泡     │
                                └──────────────┘
                                [输入框] [📎] [发送]
```

- 收起时只剩一个悬浮按钮（右下角），带未读红点
- 手机上展开就占满屏（右侧固定面板在 390px 上没有意义）

## 二、数据

**`chat_messages`**
```sql
id, from_id, to_id, body TEXT, read_at, created_at
```

一对一，不做群聊 —— 需求是「想找谁聊天就点开」，群聊是另一件事。

**附件复用 `attachments`**：`scope='chat'`，`ref_id` = 消息 id。
消息可以只有文字、只有文件，或两者都有。不再建第三张附件表。

**会话不建表**。「和谁聊过」由 `chat_messages` 里 `from_id/to_id` 涉及自己的记录推导，
建一张 conversations 表意味着每次发消息都要维护两处，容易不一致。

## 三、接口

| 端点 | 说明 |
|---|---|
| `GET /api/chat/peers` | 所有同事 + 各自未读数 + 最后一条消息预览 |
| `GET /api/chat/:userId` | 和某人的消息，按时间正序，`before` 翻旧 |
| `POST /api/chat/:userId` | 发文字 |
| `POST /api/chat/:userId/files?name=` | 发文件（原始字节，和现有上传一个路子） |
| `POST /api/chat/:userId/read` | 把对方发来的标已读 |

**权限**：只有对话双方能读，管理员也不行 —— 私聊不是台账。
`/api/files/:id` 那条路径上要加 `scope='chat'` 的检查，否则拿着连续的文件 id
就能把别人的私聊附件翻出来（工作提交那次已经踩过一模一样的坑）。

## 四、推送

复用 SSE：`publish('chat:ping', {})`，不带任何内容。
收到的人自己去拉 peers 和当前会话 —— 广播里带发件人/收件人 id 也是泄露，
而在五个人的团队里省这一次请求毫无意义。（和站内消息同一套判断。）

## 五、前端

`web/src/views/chat.js` + `index.html` 的面板骨架 + `styles.css`。

- 未读红点在悬浮按钮上，和顶栏铃铛区分开：铃铛是系统通知，这个是人对人
- 消息按天分隔，自己的靠右、对方的靠左
- 文件消息显示文件名 + 大小，点开走 `/api/files/:id`（HTML 仍走沙箱）
- 打开会话时自动标已读；新消息到达时若正开着这个会话，也立刻标已读
- 输入框 Enter 发送，Shift+Enter 换行

## 六、明确不做

- 群聊、@、撤回、已读回执（对方看没看）—— 需求里没有，加了就要维护
- 消息编辑/删除 —— 聊天记录改起来会破坏对话的可信度
- 表情面板 —— 系统自带的 emoji 键盘够用
