# 样本库第三阶段部署与验收

第三阶段增加不可变比较范围、四目标评价历史与 AI 队列、固定分析版本的作品关系、局部元素提取和经过审核的组件库。它依赖第一、二阶段全部表与约束，只能按数据库优先顺序部署。

## 上线类型与硬边界

本阶段属于 C 类数据库结构迁移。`docker compose up -d --build` 不会执行迁移，必须由 VPS 维护者在完整备份后人工运行 SQL。

- 迁移只增加表、约束、索引、函数和触发器，不删除或改写第一、二阶段业务行。
- 不修改 `.env`、Docker、Caddy、Collector、端口或媒体路径。
- 比较范围固定样本展示字段、完整分析版本、最新人工决定、十五维有效值和指标观察快照。完成后数据库拒绝修改、删除和迟到插入。
- 大媒体仍在仓库外持久目录中。本阶段不会复制、移动或删除样本媒体。
- AI 请求只发送冻结白名单，明确使用 `store:false`。没有服务端 AI Key 时不会创建任务。
- 应用回滚时保留第三阶段新表。数据库恢复必须和同一时间点的 uploads、样本媒体备份成对恢复。

迁移文件为 `scripts/migrations/20260829-sample-library-stage3.sql`，本次交付的 SHA-256 是 `d3aeaa313cce7b7787b621f542cd7b2a64ed9b5cdee37e2249b3003c48e0453c`。发布前必须在最终提交上重新核对这一值。

## 发布前一次性 PostgreSQL 17 验证

只对一次性测试库设置 `TEST_DATABASE_URL`，不得指向生产 `DATABASE_URL`。脚本会建立随机 schema，执行完整第一、二阶段结构，再把第三阶段迁移连续执行两次；随后覆盖冻结、非法归属、幂等、权限、状态机、组件可复用 DTO、AI 未配置零任务和谱系并发防环。默认结束时只删除自己创建的随机 schema。

```bash
TEST_DATABASE_URL='postgresql://.../disposable_test_database' \
  node scripts/test-sample-library-stage3-db.mjs
node scripts/test-sample-library-stage3.mjs
```

脚本会拒绝 PostgreSQL 17 以下版本，也会拒绝 `TEST_DATABASE_URL` 与当前 `DATABASE_URL` 完全相同的情况。测试通过不替代生产库备份后的迁移双跑。

## VPS 部署顺序

1. 确认 VPS 工作区无未说明改动，并记录邻居服务基线。
2. 完整备份 PostgreSQL、uploads 和仓库外样本媒体，确认三个备份均非空。
3. 快进拉取指定分支，核对最终完整 commit，不使用强制推送或历史改写。
4. 核对迁移文件 SHA-256。
5. 保存第一、二阶段关键表计数、每篇样本 current analysis ID 和关键 JSON 聚合语义。
6. 使用 `ON_ERROR_STOP=1` 执行第三阶段 SQL，随后原样再执行一次。
7. 对比迁移前后第一、二阶段计数、current ID 和 JSON 摘要；核对第三阶段表、约束、索引和触发器。
8. 重建并切换 API，等待 `/api/health` 正常。
9. 使用已登录浏览器完成第三阶段桌面、手机和权限烟测。
10. 复查邻居服务，记录实际切换时间和异常。

## 登录后烟测

- 比较管理列表只返回轻量字段，`q`、`target`、`memberId` 和分页语义正确。
- 选择 2–6 篇建立比较，冻结范围每个成员恰好十五维；新建范围不会覆盖旧评价。
- 四目标人工评价互相独立；成员不能选官方版本，评审可以。
- 无 AI Key 时显示 `AI_NOT_CONFIGURED`，数据库没有新增 job；有 Key 时任务详情不返回 provider body。
- 关系候选默认 pending；没有端点 verified evidence 不能确认；变体无方向，模仿与演化不能形成确认环。
- 局部提取至少有一个同 scope、同维度 primary；完成后不能修改。
- 组件从 draft 提交，评审批准后才进入可复用列表；changes requested 必须新建 revision；只有管理员能停用和恢复。
- reusable DTO 不包含作品点赞、浏览、排名、重证据或模型输入输出。
- 1440px 使用表格且只有矩阵容器内部可横滚；390px 使用逐维卡片且页面无横向溢出。

## 回滚

应用异常时可回退到第二阶段应用 commit 并重建 API。不要删除第三阶段新表，不要清理 uploads 或样本媒体；旧应用不会读取新增表。若必须恢复数据库，只能使用发布前 PostgreSQL 备份，并同时恢复同一时间点的 uploads 与样本媒体。回滚后再次检查 `/api/health` 和邻居服务。
