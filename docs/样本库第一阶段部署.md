# 样本库第一阶段部署与数据保护

本阶段增加“原始作品档案”，包括作品规范化记录、历次采集快照和图片/视频等媒体文件。它属于数据库结构与 Docker 持久化变更，单纯重新构建容器不会自动完成数据库迁移。

## 数据放在哪里

- PostgreSQL：`samples`、`sample_captures`、`sample_assets` 保存作品字段、每次采集的原始 JSON 和媒体元数据。
- VPS 宿主机：媒体字节默认保存在 `/opt/ideahub-samples`，通过只给 API 容器使用的挂载目录读取。
- Git：不保存样本图片、视频和音频；这些文件不会随 `git pull` 或镜像重建消失，也不会进入仓库。
- Collector：采集任务仍保存在 `/opt/ideahub-collector`。自动归档成功后，IdeaHub 会把所需媒体复制到自己的样本目录，后续回看不再依赖 Collector 临时任务目录。

## 第一次上线顺序

1. 确认 VPS 在 `feat/content-collector` 分支，工作区只有预期的 `.env` 本地配置改动。
2. 备份 PostgreSQL。
3. 快进拉取本阶段提交，禁止强推或覆盖服务器产生的新备份提交。
4. 创建 `/opt/ideahub-samples`。
5. 对现有数据库执行 `scripts/migrations/20260829-sample-library-stage1.sql`。该脚本可重复执行，不删除旧表和旧数据。
6. 重新构建并启动 `api` 与 `collector`，让新的容器挂载和自动归档地址生效。
7. 在 API 容器内运行 `scripts/migrate-work-analyses-to-samples.mjs`，把当前可见、未软删除的 `work_analyses` 建立为样本，并复制已落地的封面/图文图片。脚本可重复执行，旧记录保持原样；已经被业务人员软删除的作品不会在样本库中意外复活。
8. 检查 API、Collector、数据库表、迁移数量和样本页面。

## VPS 可复制执行命令

下面路径与当前 VPS 约定一致。执行前先确认服务器工作区只有既有的 `.env` 本地改动；如果出现其他未知改动，停止并先处理，不能覆盖。

```bash
set -euo pipefail
cd /root/ideahub-deploy

git status --short --branch
git fetch origin feat/content-collector
git pull --ff-only origin feat/content-collector

mkdir -p /root/backup /opt/ideahub-samples
chmod 700 /opt/ideahub-samples
backup_file="/root/backup/ideahub-pre-samples-$(date +%Y%m%d-%H%M%S).sql"
docker compose exec -T db pg_dump -U ideahub -d ideahub > "$backup_file"
test -s "$backup_file"

docker compose exec -T db psql -v ON_ERROR_STOP=1 -U ideahub -d ideahub \
  < scripts/migrations/20260829-sample-library-stage1.sql

docker compose exec -T db psql -v ON_ERROR_STOP=1 -U ideahub -d ideahub -Atc \
  "SELECT to_regclass('public.samples'),to_regclass('public.sample_captures'),to_regclass('public.sample_assets');"

docker compose config --quiet
bash scripts/check-collector-vps.sh
docker compose up -d --build api collector

docker compose exec -T api node scripts/migrate-work-analyses-to-samples.mjs
first_counts="$(docker compose exec -T db psql -U ideahub -d ideahub -Atc \
  "SELECT count(*)||':'||(SELECT count(*) FROM sample_captures)||':'||(SELECT count(*) FROM sample_assets) FROM samples;")"
docker compose exec -T api node scripts/migrate-work-analyses-to-samples.mjs
second_counts="$(docker compose exec -T db psql -U ideahub -d ideahub -Atc \
  "SELECT count(*)||':'||(SELECT count(*) FROM sample_captures)||':'||(SELECT count(*) FROM sample_assets) FROM samples;")"
test "$first_counts" = "$second_counts"

docker compose ps
curl -fsS http://127.0.0.1:18080/api/health
docker compose exec -T db psql -U ideahub -d ideahub -c \
  "SELECT archive_status,count(*) FROM samples WHERE deleted_at IS NULL GROUP BY archive_status ORDER BY archive_status;"
```

最后在浏览器强制刷新，依次检查：样本库列表、完整样本详情、图片回看、视频拖动播放、手动录入、给当前样本补媒体。迁移脚本输出若包含 `errors` 或两次计数不一致，不要继续宣布上线，应保留当前容器和备份后排查。

## 回滚边界

- 应用回滚：可以切回上一提交并重新构建；新增样本表和 `/opt/ideahub-samples` 不影响旧页面。
- 数据回滚：默认不要删除新表、不要删除样本媒体目录。应用回滚后保留数据，修复后可继续使用。
- 只有明确决定永久放弃样本库，并完成单独备份后，才可以另行设计删除表/目录的操作；本阶段不提供自动清理命令。

## 备份要求

数据库备份不包含媒体文件。VPS 备份必须同时覆盖：

- PostgreSQL 逻辑备份；
- `/opt/ideahub-samples`；
- 原有 `/opt/ideahub-collector/state` 与 `/opt/ideahub-collector/output`。

本次已同步更新 `scripts/backup.sh`：每日任务除数据库和 `data/uploads` 外，还会生成 `sample-assets-时间.tar.gz`，并沿用 `BACKUP_KEEP_DAYS`。上线后必须手动执行一次并确认三类文件都存在：

```bash
cd /root/ideahub-deploy
BACKUP_DIR=/root/backup/ideahub SAMPLE_ASSET_PATH=/opt/ideahub-samples sh scripts/backup.sh
ls -lh /root/backup/ideahub/*
tar tzf "$(ls -1t /root/backup/ideahub/sample-assets-*.tar.gz | head -1)" | head
```

恢复媒体时必须与同一时间点的数据库备份配套。先停止 API 写入，确认恢复包内容不含绝对路径或 `..`，再解压到 `/opt`：

```bash
cd /root/ideahub-deploy
sample_backup=/root/backup/ideahub/sample-assets-需要恢复的时间.tar.gz
test -s "$sample_backup"
if tar tzf "$sample_backup" | grep -Eq '(^/|(^|/)\.\.(/|$))'; then echo "不安全的备份路径"; exit 1; fi
docker compose stop api
mkdir -p /opt/ideahub-samples
tar xzf "$sample_backup" -C /opt
docker compose up -d api
curl -fsS http://127.0.0.1:18080/api/health
```

当前是本机磁盘备份流程，还没有异机/对象存储副本。若要抵御 VPS 整盘故障，应由维护者再把 `/root/backup/ideahub` 同步到受控的异机存储；在异机备份未配置前，不应把“永久归档”理解为能够抵御整台 VPS 丢失。

## 验收清单

- 链接采集完成后，样本库自动出现作品；刷新浏览器仍可查看。
- 当前单篇作品最多归档 50 张图片；超过上限会拒绝并明确报错，不会以“完整”状态静默少存。
- 手动录入可保存部分档案，并明确显示缺失字段与完整度。
- 图片、视频和封面可直接在站内查看；视频支持 Range 请求和拖动播放。
- 同一作品重复采集只保留一个样本，但“历次原始采集”新增快照。
- 老对标作品仍可在原页面使用，同时在样本库中可回看。
- 容器重建后样本媒体仍存在。
